# 画像与历史摘要的长期记忆

所有业务、原始对话、记忆队列、画像和摘要共用 PostgreSQL。pgvector 提供语义检索；Redis 仅缓存近期聊天上下文和消息列表，详见[缓存说明](../redis/README.md)。

## 配置

在 `server/.env` 中配置独立的文本向量服务：

```dotenv
MEMORY_ENABLED=true
MEMORY_EMBEDDING_BASE_URL=https://YOUR-PROVIDER/API-PREFIX/v1
MEMORY_EMBEDDING_API_KEY=你的向量服务密钥
MEMORY_EMBEDDING_MODEL=服务商支持的文本向量模型
MEMORY_EMBEDDING_DIMENSIONS=1024
MEMORY_MIN_SIMILARITY=0.5
MEMORY_SUMMARY_MIN_MESSAGES=6
MEMORY_WRITE_MODE=auto
```

地址包含 API 前缀，不包含 `/embeddings`；服务需支持 OpenAI 兼容的向量接口及 `dimensions` 参数。对话模型和 embedding 服务分别配置和计费，不能把 DeepSeek 对话 Key 直接用作向量 Key。`MEMORY_DATABASE_URL` 已废弃，应移除；统一连接使用 `DATABASE_URL`。

配置后先执行 `npm --prefix server run embedding:check`。检查器读取 `server/.env`，调用 3 次真实向量接口（云服务可能计费），仅使用自带的学习和做菜示例文字，在 PostgreSQL 临时表中验证向量维度和语义排序，不发送或写入用户记忆。已有向量空间不兼容时会在调用前拒绝检查。`semantic_sample: passed` 仅表示这组样例通过，不代表真实召回质量已全面评估。验证成功后重启 API；画像提取、摘要生成还需要用户在网页上绑定可用的对话模型 Key。

未配置向量服务时，普通业务和问答正常运行，语义记忆暂不启用。也可设置 `MEMORY_ENABLED=false` 显式关闭。`MEMORY_WRITE_MODE=off` 暂停自动写入，`explicit` 仅在明确要求记住时提取画像，默认 `auto` 自动提取稳定信息。

## 写入

1. 用户消息与画像任务在同一 PostgreSQL 事务内保存。
2. 后台仅从用户原话提取学习偏好、目标和薄弱点，要求逐字证据和至少 0.85 的置信度；稳定主题 key 用于更新同一属性。
3. 事实向量化后保存，每条最多 600 字符。助手建议、假设、第三人称描述不应成为用户事实。
4. 助手回答与会话摘要任务也在同一事务中保存。默认积累 6 条消息后处理，每段最多 12 条、限制输入长度。
5. 新建或切换到其他会话时，安排旧会话尾段摘要。摘要保留源会话、起止消息 ID、文本哈希、版本和向量空间标识。

历史摘要记录讨论的主题、解决进度、用户明确决定和待解决问题，与稳定画像分开管理。后台任务采用租约、跳锁领取和失败退避；进程重启后可继续处理。摘要任务幂等，不重复生成已覆盖的消息范围。

用户明确说“不要记录”等时，该条个人消息及对应助手回答不会加入语义记忆。原始聊天仍作为正常聊天记录保存。

## 召回

```text
当前问题 → embedding（一次）
    ├─ 当前用户画像：最多 6 条，约 4000 字符
    └─ 当前用户相关历史摘要：最多 4 段，约 3500 字符
                ↓
系统规则 + 最近 12 条消息/附件 + 画像 + 历史摘要 + 本轮工具结果
```

两类召回均执行用户过滤、余弦相似度阈值和向量空间校验。当前会话中仍处于近期窗口的摘要不重复注入；较早的本会话摘要可以按问题召回。初版使用按用户过滤后的精确向量搜索，避免共享 ANN 索引后置过滤导致漏召回；规模扩大后再评估分区 HNSW。

记忆是资料，不是指令；不会授予工具权限，当前用户更正优先。embedding 或数据库故障时，回答会明确缺少历史记忆并继续使用当前上下文。

## 查看、修改与删除

学习问答和行动工作台侧栏均有“跨会话长期记忆”入口。可查看画像、原话证据、历史摘要及其来源范围，修改画像后重新生成向量。

为避免旧事实通过历史摘要再次召回，修改或删除画像会清空已有历史摘要的正文和向量，并设置隐私水位。清除摘要同样阻止旧消息重新回填这些内容；之后只从水位之后的新消息积累摘要。这个策略会同时清除其他旧摘要，是初版为保证遗忘一致性采用的保守范围。原始聊天不会随之删除，同一会话的近期原话仍可能出现在短期窗口。

手工修改的画像优先于后续自动提取。删除的主题保留最小删除标记，旧任务不能恢复；账户注销在同一个数据库事务中清除个人业务数据和记忆，最小的已注销 ID 标记用于阻止在途任务重建。

## 限制与验证

更换 embedding 地址、模型或维度时必须迁移向量空间并重新向量化，不能混用旧向量。初始阈值 0.5 需要用真实学习问题校准，模型提取和摘要仍可能出错，必须保留人工纠正入口。

历史消息的回填命令、SQLite 导入、部署和测试步骤见 [数据库说明](../postgres/README.md)。测试使用真实 PostgreSQL/pgvector 和本地模拟模型；没有声称验证过真实提供商的质量或额度。
