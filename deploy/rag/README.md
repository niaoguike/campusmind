# 课程资料混合检索

聊天的资料检索工具和课程出题共用 `server/services/rag/`。课程库正文与个人画像、历史对话摘要分别存储，检索课程资料时不读取私人聊天或个人记忆。

## 已实现的流程

```text
文件 → 章节/段落/题解切分 → 子片段 + 完整父段落 + 页码范围
                         ├─ 中文分词 → PostgreSQL GIN 全文索引
                         └─ 持久队列 → 本地 BGE-M3 → pgvector

问题 → 多轮追问补全 → 关键词与向量并行召回 → RRF → 可选 Rerank
                                                  → 去重并展开父段落 → 带来源的证据
```

- **Chunking**：子片段目标 700 字符，父段落目标 2200 字符。优先保留段落、代码、公式和题目与解答；正常原子块可超过目标，上限 2400 字符，超长块按句子/行再切分。重叠仅复用完整的末尾短段（最多 100 字符）。跨页题解可合并并记录页码范围，幻灯片/工作表之间保留边界。PDF 保存真实页码，DOCX 没有可靠分页时保留空页码。扫描件仍需 OCR 后才能检索。
- **关键词召回**：使用 Node 内置 `Intl.Segmenter` 做中文分词，写入 PostgreSQL `tsvector` 与 GIN 索引，以 `ts_rank_cd` 和词项覆盖率排序。标题、课程、章节等元数据参与检索。提供常见课程简称扩展；它不是 BM25。
- **向量召回**：独立的 `resource_chunk_vectors` 表保存片段向量，按余弦相似度检索。小规模资料库使用精确检索；默认候选阈值 0.45，生产阈值应结合真实标注问题评估。模型地址、模型名和维度共同标记向量空间，切换模型会重新排队，空间之间不会混用。
- **RRF**：两路各召回至少 20 条，按 `Σ 1/(60+rank)` 融合，同一片段只计一次。融合不直接混合不同检索器的分数，也不按置顶或上传时间排相关性。
- **上下文**：命中子片段后优先回带父段落，按父段落去重，总正文预算 7000 字符；预算不足时退回完整子片段，再不足就跳过。返回文件链接、资源和片段 ID、章节、页码范围及两路排名。不再直接截取前 900 字。
- **范围**：两路都只检索审核通过且正文索引可用的资料；出题时始终使用所选课程。通用聊天默认检索平台课程库，与当前平台的共享资料权限一致。
- **更新**：业务元数据修改或课程更名立即使旧向量失效，后台更新词项并重新向量化。正文重建会原子替换片段，级联清除旧向量与任务。写入队列持久化、租约抢占、最多 5 次重试；旧租约结果不能覆盖重建后的索引。

## 本机启用与历史重建

沿用[本地 Ollama + BGE-M3 配置](../embeddings/README.md)，无需增加云端 Key。RAG 默认继承 `MEMORY_EMBEDDING_*`，可用同名的 `RAG_EMBEDDING_*` 单独覆盖；不依赖 `MEMORY_ENABLED`。关闭向量一路可设 `RAG_VECTOR_ENABLED=false`，关键词一路仍工作。

```powershell
# 应用新增表与字段；启动 API 也会自动迁移
npm --prefix server run db:migrate
# 重建旧切分，补齐中文索引和向量；只读取已上传的源文件
npm --prefix server run rag:reindex -- --vectors
# 重建全部文件，或手动重试已达到重试上限的任务
npm --prefix server run rag:reindex -- --force --vectors --retry-failed
```

API 启动后自动扫描旧文件切分并重建；后台每 30 秒补索引，每 1.5 秒尝试领取一个向量任务，单进程串行，适合本地 CPU。重建期间相关文件暂不可检索；向量尚未就绪或服务故障时保留关键词召回。找不到源文件时需重新上传，脚本会报告资源 ID。数据量大时应独立运行索引 worker、建立固定维度 ANN 索引并评估召回损失。

## Query Rewrite

`RAG_QUERY_REWRITE=rules` 为默认：只对“它、刚才、继续”等多轮追问，从当前会话近期的用户问题补回主题，过滤助手和系统消息，无额外模型调用。不明确的追问且无主题前文时保留原查询。

设为 `model` 后，个人聊天才按需使用用户当前对话模型做独立问题改写，最多等待 2 秒；异常或格式错误回退规则。该模式会增加对话模型调用与费用。`off` 完全关闭。规则补全是启发式方法，复杂主题切换需进一步评估。

## 可选 Rerank

默认关闭。当前 BGE-M3 负责向量化，重排需要另一个支持 Jina/Cohere 风格接口的 Cross-Encoder 服务；可以以后独立部署本地服务，也可以使用云服务。

```dotenv
RAG_RERANK_ENABLED=true
RAG_RERANK_URL=http://127.0.0.1:8001/v1/rerank
RAG_RERANK_MODEL=服务实际支持的重排模型
RAG_RERANK_API_KEY=
RAG_RERANK_TIMEOUT_MS=3000
```

候选数大于返回条数时才重排，最多发送 40 个已有片段。只接受原候选索引，不允许新增结果；超时、故障或非法索引均回退 RRF。远程地址须用 HTTPS。启用远程重排会把候选课程正文发给所配置的服务，并按其规则计费。

## 验证与限制

```powershell
npm --prefix server run test:rag
npm --prefix server run test:rag:postgres
# 需要本机已启动的 BGE-M3，实际调用本地模型，不调用云端对话模型
npm --prefix server run test:rag:local
```

数据库测试使用独立 schema，覆盖两路互补、RRF、课程/审核过滤、更新失效、删除、并发租约和失败降级。本机实测包括英文 `knapsack optimization` 召回中文背包资料、两路同时命中和多轮追问。样例通过不等于生产质量已评估：下一步应从实际课程收集问题及相关片段标注，比较 Recall@20、MRR/NDCG、来源完整性和 P95 延迟，再决定是否开启 Rerank、调整阈值或增加 ANN。
