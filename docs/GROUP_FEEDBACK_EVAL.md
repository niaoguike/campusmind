# 群聊学习反馈验收与 MAD 对照

本功能默认关闭。群主开启群 AI 观察后，每位成员仍须单独允许自己的新消息用于本群分析。未授权成员的消息不会进入上下文。旧消息不会自动追溯授权。反馈默认只对发起者可见，不写回普通群聊。

## 手工验收

1. 用群主账号进入学习群，点“AI 学习反馈”，开启观察，先选择“仅 @AI 或手动”，分析模式选择“单 Agent”，保存。
2. 用两名成员分别打开同一设置，一人授权，一人保持关闭。两人各发一条消息。确认未授权成员的消息没有“请 AI 帮忙”入口，也不进入反馈上下文。
3. 授权成员发送 `@AI 为什么二分查找必须保持区间不变量？`。几秒后消息旁出现私有反馈状态；打开查看摘要、来源和证据不足提示。另一名成员看不到反馈。
4. 授权成员在自己的另一条消息点“请 AI 帮忙”，查看分析状态并继续追问。确认普通群聊里没有自动出现反馈文本。
5. 发起者主动“分享给小组”，另一成员此时可见；再改回私有后不可见。
6. 编辑或删除锚点消息，查看反馈显示过期提示。撤销任一成员授权，确认本群已有反馈被隐藏。
7. 连续发 60 条消息，验证默认只加载最新 50 条，点击“加载更早消息”继续向前翻页；非法 `before`、跨群回复与越权编辑应被拒绝。
8. 在设置里依次选择单 Agent、单 Agent + 自查、自由讨论、独立分析 + 证据核验，用同一个新问题分别发起反馈，记录实际响应、模型调用次数和耗时。相同消息的不同模式可创建不同任务；相同模式会去重。

## 研究评估

先请教师准备开发集和独立测试集，标注问题答案、错误步骤、可引用课程证据和合适的介入时机。固定同一模型、课程材料、消息窗口，记录每个模式的调用次数、延迟、人工判定的纠错准确率、证据支持率、错误共识率和学生后测表现。四种模式调用预算不同，报告时应单列成本和延迟；不能把模型自报置信度当作准确率。尚无标注集时，不宣称 MAD 优于单 Agent。

## 当前边界

- 自动触发默认只响应明确 `@AI`；“求助线索建议”会先经规则筛选，再调用分类模型判断。规则并不能覆盖所有值得介入的消息。
- 分析仅使用最多 12 条已授权群消息和该课程最多 4 条已审核资料检索结果。无课程证据时标记“证据不足”。
- 个人 Agent 参与此反馈流程属于后续阶段；现有群 Agent 功能独立存在。
- 队列在单进程内运行；进程重启时未完成任务会标记失败。生产多实例时需迁移至持久化工作队列。
- 反馈尚未做自动到期清理；撤权、撤回、消息删除和群解散会控制可见性或删除锚点。上线前需按项目隐私要求确定保存期限。
